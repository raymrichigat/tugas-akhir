## 5. Benang merah per kelas

| Kelas | Kecenderungan error | Penyebab utama |
|---|---|---|
| PERSON | Kuat, tapi penyumbang FP terbanyak | Honorifik (Shalallahu/Alaihi) & nasab (bin/Abu/Abdul) ikut tertarik jadi nama |
| TIME | Precision terendah | Kata waktu generik (bulan/hari) + inkonsistensi gold huruf kecil (pertengahan/malam) |
| EVENT | F1 rendah, satu-satunya yang tertukar jenis | Few-shot + ambiguitas nama tempat = nama perang (Uhud, Badr, Hudaibiyah) |
| LOCATION | Stabil, error sisa di batas kata | Artefak OCR (tanda baca menempel: Babilonia., Umayyah.) |

**Dua temuan besar yang bertahan dari run ke run:**
1. **Model jarang salah jenis, lebih sering salah deteksi.** Misklasifikasi tipe cuma 5–10 token (dari ~240) di semua skenario sehat → model paham beda 4 tipe; yang sulit adalah menarik garis entitas vs kata biasa. Terlihat di panel confusion (diagonal ~1,0).
2. **EVENT & TIME selalu paling sulit** karena few-shot — urutan F1 per kelas (EVENT/TIME < LOCATION < PERSON) mengikuti urutan kelangkaan datanya.

**Satu temuan yang BERUBAH di run ini:** di data gold terkoreksi, **augmentation tidak lagi mengangkat minoritas secara konsisten** (EVENT terbaik jscl, TIME terbaik baseline/pos-tag). Ini perlu disampaikan jujur — beda dari klaim run lama.

## 9. Lampiran: rumus & pendekatan metode penanganan imbalance (S1)

Menjelaskan tiga metode S1 selain augmentation: **weighted cross-entropy**, **SCL**, **JSCL**. Sumber rumus: `docs/skenario/srl_ner.md` (Khosla et al. 2020 untuk SCL; Dewabharata et al. untuk JSCL) + `src/pseudo_labelling/SRL-NER/build_class_weights.py`.

### 9.1 Titik awal: Cross-Entropy biasa (baseline)

```
L_CE = -(1/N) Σ_i  log p(y_i | x_i)
```

Untuk tiap token ke-`i`, ambil probabilitas model pada label benar (`y_i`), hukum model kalau kecil. Masalah: token `O` dan PERSON jauh lebih banyak, jadi model bisa dapat loss kecil hanya dengan jago di kelas mayoritas sambil mengabaikan EVENT/TIME.

### 9.2 Weighted Cross-Entropy (skenario weighted-CE)

```
L_weighted = -(1/N) Σ_i  w[y_i] · log p(y_i | x_i)
```

`w[c]` = bobot kelas. Skema **sqrt_tempered_norm_O1**: akar dari inverse-frequency lalu dinormalisasi supaya `O = 1,0` (meredam agar tidak ekstrem). Bobot dihitung ulang dari gold terkoreksi via `build_class_weights.py`; urutan besaran: `O = 1,0`, kelas entitas minoritas (B-EVENT, I-LOCATION, B-TIME) mendapat bobot **belasan hingga puluhan kali** lebih berat.

**Kenapa malah turun (F1 0,9333 < baseline 0,9420):** memaksa perhatian ke minoritas membuat model **over-deteksi** — FP tertinggi di S1 (**175 token**), precision turun paling banyak (0,9131 vs 0,9255) sementara recall praktis sama. "Memberi bobot" saja tidak cukup; model perlu contoh nyata (keunggulan augmentation).

### 9.3 Supervised Contrastive Learning / SCL (skenario scl)

Membenahi **representasi** (embedding) token, bukan loss klasifikasi. Token sekelas ditarik berdekatan, beda kelas didorong menjauh.

```
p_ij  = exp(sim(z_i, z_j)/τ) / Σ_k exp(sim(z_i, z_k)/τ)
L_SCL = Σ_i  (-1/|P(i)|) Σ_{j ∈ P(i)} log p_ij
L_total = (1 - λ_C) · L_CE + λ_C · L_SCL
```

`sim` = cosine similarity, `τ` = 0,1, `P(i)` = token sebatch yang **labelnya sama persis** (InfoNCE), `λ_C = 0,3`. **Hasil:** 0,9409 — setara baseline (macro 0,8922), PERSON tertinggi (0,9581). Merapikan, tapi tidak menambah contoh minoritas.

### 9.4 Jaccard Similarity Contrastive Learning / JSCL (skenario jscl)

Varian SCL lebih "lunak" di **level kalimat**: dua kalimat yang sebagian labelnya tumpang tindih tetap saling ditarik, sebanding tumpang tindihnya.

```
J_ij = |L_i ∩ L_j| / |L_i ∪ L_j|        (Jaccard bag-of-labels kalimat, tanpa O)
α_ij = J_ij / (Σ_k J_ik + ε)
L_JSCL = -(1/B) Σ_i Σ_j  α_ij · log( exp(sim(s_i, s_j)/τ) / Σ_k exp(sim(s_i, s_k)/τ) )
```

`s_i` = embedding kalimat (rata-rata token). **Hasil:** 0,9344, **di bawah baseline & SCL** (EVENT tertinggi 0,9054 tapi TIME terendah 0,7534). **SCL > JSCL** konsisten; dugaan: sinyal sentence-level lebih kabur untuk tugas token-level.

### 9.5 Ringkas perbandingan (run gold terkoreksi)

| Metode | Bekerja di level | Inti | micro F1 | Catatan |
|---|---|---|---:|---|
| baseline (CE) | loss klasifikasi | `-Σ log p(y_i)` | 0,9420 | acuan |
| weighted-CE | loss klasifikasi berbobot | `-Σ w[y_i] log p(y_i)` | 0,9333 | over-deteksi, precision turun |
| scl | representasi (token) | InfoNCE token sekelas | 0,9409 | setara baseline |
| jscl | representasi (kalimat) | InfoNCE berbobot Jaccard | 0,9344 | SCL > JSCL |
| **augmentation** | **data** | tambah kalimat (ganti entitas) | **0,9458** | **juara micro (via PERSON)** |

**Pelajaran (Bab 4):** tiga metode pertama mengutak-atik **cara belajar dari data yang sama**; hanya augmentation yang **menambah data**. Di dataset few-shot, menambah contoh nyata unggul — **tapi** di run gold terkoreksi keunggulannya menyempit & tidak lagi konsisten di kelas minoritas (disclosure jujur, beda dari run lama).
